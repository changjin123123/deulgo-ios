# 들고 · iPhone 앱

물건을 보내는 사람과 가는 김에 운반하는 사람을 위한 SwiftUI 앱의 첫 통합 구현이다. iPhone부터 완성하고 Android는 그다음 진행한다.

0.1.5 (6)는 **iPhone 기기용 빌드 성공 · XCTest 43개 및 규칙 검사 10개 통과** 상태다. 후루츠패밀리 앱 공유 주소와 번개장터 상품 조회를 수정했고 당근 제목의 별도 가격·서비스 표기를 제거했다. 보내기 입력 화면과 키보드 동작, 홈의 장거리 운반·요청 둘러보기, 기존 헬로마켓 지원을 유지한다. 카카오 설정 포함 검사도 통과했다. 실제 이용자 간 배차·결제 서비스는 아직 아니며, 새 버전의 실기기 상품 조회와 외부 내비 목적지 전달은 확인 전이다.

[성공한 빌드와 산출물](https://github.com/changjin123123/deulgo-ios/actions/runs/46038728209) · [Windows에서 iPhone 테스트 설치](INSTALL.md) · [검증 범위](VALIDATION.md)

## 현재 확인판 · 0.1.5 (6)

후루츠패밀리 앱 공유 주소 해석, 번개장터 공개 상품명·첫 사진 조회, 당근 메타 제목의 가격·서비스 표기 정리, 잘못된 링크의 즉시 안내를 수정했다. [실행 #12](https://github.com/changjin123123/deulgo-ios/actions/runs/46038728209)에서 규칙 10개·구조 검사·XCTest 43개가 통과했고 오류 안내와 빈 보내기 화면을 확인했다. 기존 소유자 승인 후 기기용 빌드·키 설정 검사·임시 설정 삭제가 성공했다. 내려받은 0.1.5 (6) IPA의 버전·arm64·무결성도 확인했다. 새 버전의 실기기 사진·상품명 조회는 확인 전이다. [조회 방식과 확인 범위](LISTING_LINKS.md).

0.1.5 실기기에서 후루츠패밀리 공유 주소 해석 실패가 보고됐다. 같은 상품의 일반 주소로 물품명·사진이 표시되는 사용자 확인을 받았고, iOS 계열 요청에 공유 서버가 주는 200 앱 실행 HTML을 처리하지 못한 경우를 재현해 **0.1.6 (7)**에서 수정했다. 실제 응답 구조를 반영한 단위 검사 3개를 추가했다. [실행 #13](https://github.com/changjin123123/deulgo-ios/actions/runs/46044004090)에서 구조·규칙 10개·XCTest 46개가 통과했고 실패·건너뜀은 0이다. 새 기기 빌드는 기존 소유자 승인 대기 중이며 0.1.6의 실기기 공유 링크 조회는 확인 전이다.

번개장터도 실기기에서 공유 주소는 실패하고 일반 상품 주소는 물품명·사진이 표시되는 것으로 확인됐다. 버전이 포함된 CFNetwork/Darwin 요청이 번개장터의 Airbridge 중간 주소로 이동하는 경우를 재현했고, 그 상품 번호를 검증해 일반 상품 주소로 바꾸도록 **0.1.6 (8)**에 추가 수정했다. 앞선 빌드 7의 배포 승인은 보류한다. 새 단위 검사 3개를 포함한 XCTest 49개 실행과 새 기기 빌드는 아직 전이다.

## 이전 확인판 · 0.1.3 (4)

- 보내기 첫 화면은 링크 입력칸만 테두리로 구분한다. 링크 자동 입력 안내는 테두리 밖에 두고, 직접 입력 안내는 `무엇을 보낼까요?` 아래에 배치한다.
- 키보드는 상단 닫기 버튼, 입력칸 밖 안내·여백 누르기, 아래로 스크롤하기로 내릴 수 있게 구성했다. 키보드가 보일 때는 하단 다음 버튼과 탭을 숨기고 닫힌 뒤 원래 하단으로 복원한다.
- 재조회·내용 붙여넣기는 조회 실패 시에만 표시한다. 물품 상세는 선택 항목으로 접어 둔다.
- 홈에 `가는 김에 · 장거리 운반` 영역을 두고 `운반 요청 둘러보기`로 직접 진입한다. 공개 요청 서버는 아직 연결되지 않았으며 준비 중 상태를 표시한다.

## 이전 확인판 · 0.1.2 (3)

아래 변경을 포함한 새 iPhone 빌드가 2026-11-27 01:07 KST에 성공했다. 실제 iPhone 업데이트 설치와 전체 화면 직접 조작은 아직 확인 전이다.

- 허용한 거래글 링크 입력 후 자동 조회하고 물품명을 바로 채운다. 별도의 물품 정보 적용 버튼은 없다. 조회 실패 시 다시 불러오기·내용 붙여넣기·직접 입력을 사용할 수 있다.
- 직접 수정한 물품명·치수는 자동 조회로 덮어쓰지 않는다. 링크를 바꾸거나 지우면 그 링크에서 자동으로 채운 값만 정리한다.
- 수량 입력칸을 제거했다. 새 요청의 수량은 미확인으로 보관하며 링크 하나를 물품 한 개로 간주하지 않는다. 이전판의 입력 수량은 유지한다.
- 포장·크기·운반 방향은 접힌 선택 항목이며 기본 상태는 확인 필요다. 미확인 수량·방향으로 긍정적인 적재 판정을 내리지 않는다.
- 픽업지는 물건 있는 곳의 주소를 입력한다. 다른 사람의 물건은 건네줄 사람에게 확인한다. 임시 보관에서는 비워둘 수 있고 받을 곳은 입력해야 한다. 주소록 선택·저장은 도착지에만 표시한다. 링크로 정확한 판매자 주소를 추정하지 않는다.
- 마지막 주 버튼은 `운반 요청 올리기`다. 실제 공개·운반자 접수 기능이 없는 현재는 준비 중으로 비활성화하고, `작성 내용 임시 보관`을 별도 동작으로 제공한다. 임시 보관을 게시 성공으로 표시하지 않는다.
- 운반자 준수사항은 접기 없이 표시하며 검토안 표시는 유지한다.

서비스 문구는 **가는 김에**로 통일한다. 중고거래 구매자 외에도 본인 물품·가족이나 지인에게 보낼 물품의 운반을 요청할 수 있도록, 거래글 링크를 선택 사항으로 유지하고 기본 안내를 특정 거래 역할에 한정하지 않는다. 기존 자료의 판매자 확인 필요 표시는 확인 필요로 호환 표시한다.

운반하기 첫 번째 메뉴는 **운반 요청 둘러보기**다. 현재는 전용 화면과 연결 준비 안내를 제공하며, 내 임시 보관 자료나 예시 데이터를 다른 이용자의 공개 요청으로 표시하지 않는다. 차량 등록·수정과 준비 정보는 그 아래에 둔다.

공개 기능 연결 시 요청 목록의 설계는 다음과 같다. 이 표는 아직 구현된 서버 기능을 의미하지 않는다.

| 위치 | 표시·동작 계획 |
|---|---|
| 운반하기 → 운반 요청 둘러보기 | 중고거래·일반 물품 요청을 같은 목록에서 조회 |
| 요청 카드 | 물품명, 픽업 동네 → 도착 동네, 희망 시간, 제안 운반비(미정이면 미정 표시) |
| 목록 찾기 | 픽업 지역·도착 방향·희망 시간으로 좁히기 |
| 요청 상세 | 확인된 물품 정보·운반 조건 확인 후 운반 신청 |
| 내역 | 내가 올린 요청·신청한 운반의 상태 관리 |

전체 주소·상세주소는 공개 목록에 표시하지 않고 배정된 운반자에게 필요한 범위로 제공하는 구조가 필요하다. 게시·신청·배정의 실제 서버 처리와 접근 권한은 후속 구현 범위다.

자동 입력 보호, 링크 변경, 기존 자료 읽기, 픽업지 미확인 보관, 적재 판정 관련 XCTest 7개를 추가했다. 총 28개 XCTest는 승인된 실행 #6에서 모두 통과했다.

| 화면 | 동작 |
|---|---|
| 홈 | 보내기·운반하기 진입, 최근 저장 요청 |
| 보내기 | 거래글 자동 조회 → 물품명 → 주소 → 확인, 게시 준비 중 표시 및 임시 보관 |
| 거래글 | 상품 링크 검증·짧은 공유 주소 해석, 번개장터 공개 상품 응답 또는 Apple LinkPresentation 조회·물품명 채우기, 사진·제목 중심 접힌 설명 |
| 주소 | Apple 지도 검색 결과 확인, 픽업지 나중에 입력 가능, 도착지 주소 저장·재사용 |
| 운반하기 | 상단 요청 둘러보기 진입(공개 연결 준비 중), 차량 등록·수정·삭제, 차종 초성/별칭 검색, 2010년 이후 연식 또는 몰라요 |
| 차량 자료 | 기존 2010년 이후 적재 용량 자료의 L 값·출처·판본·상세 치수 조건 표시 |
| 조건 비교 | 직접 입력한 치수·무게·인원·장비 비교, 누락값은 확인 필요로 표시 |
| 내역 | 저장한 요청 조회·검색·수정·삭제, 확인된 좌표를 길 안내로 전달 |
| 내 정보 | 기기 저장 상태·주소록·현재 이용 범위 |
| 길 안내 | 카카오내비·네이버지도 목적지 전달, 미설치·실패 안내 |

물품 가격 입력은 없다. 차량 제원은 운반자 화면에만 있다. 차량 이름을 따로 붙일 필요 없이 모델명으로 표시한다. 치수는 선택 입력이다. L 용량을 차량 내부 치수로 환산하거나 적재 가능 판정에 사용하지 않는다.

## 데이터와 동작 경계

요청·주소·차량은 이 기기의 Application Support 보호 파일에 원자적으로 저장하며 iCloud 백업 대상에서 제외한다. 저장 실패 시 화면 상태를 저장 성공 상태로 바꾸지 않는다. 읽을 수 없는 기존 파일도 새 빈 파일로 덮어쓰지 않는다. 기기 변경·앱 삭제 전에 데이터 이동 기능이 별도로 필요하다.

주소의 기본 텍스트를 수정하면 기존 좌표를 무효화한다. 상세주소는 내비 앱에 전송하지 않는다. 검색어만 Apple 지도에 전송하고 사용자가 지도·주소를 확인한 결과만 목적지로 사용한다. 기본 위치 권한은 요청하지 않으며 운전 시작 위치는 외부 내비가 처리한다.

거래글은 허용한 상품 링크만 조회한다. 번개장터는 공개 상품 페이지가 쓰는 비로그인 응답에서 일치하는 상품명·첫 사진을 읽고, 다른 서비스는 Apple LinkPresentation으로 공개 정보를 요청한다. 두 서비스의 허용된 짧은 공유 주소는 같은 서비스의 상품 주소로 먼저 해석한다. 기존 웹 서버와 다른 조회 경로이므로 실제 플랫폼별 성공 여부는 iPhone에서 재확인해야 한다. 당근부동산·카페·허용되지 않은 호스트는 상품 조회 대상으로 받지 않는다. 불러오지 못하면 복사한 내용 또는 직접 입력을 사용한다. 가격은 요청 필드로 가져오지 않는다. 자동 입력은 빈 값 또는 앞서 자동 입력한 값에만 적용하고 사용자가 직접 수정한 값은 보존한다.

운반자 준수사항은 기존 시제품 문구를 **검토안** 표시와 함께 유지했다. 법적 효력·처벌·보험 보장 확정을 의미하지 않는다.

- `CarrierViews.swift`: 차량 등록·모델 선택·적재 자료
- `RequestHistory.swift`: 요청 내역·조건 비교
- `AppStore.swift`: 기기 저장
- `ListingImport.swift`: 상품 링크 검증·공개 미리보기
- `ReferenceData.swift`, `Resources/`: 기존 순수 규칙과 차량 참고 자료
- `Navigation*.swift`, `ExternalNavigation.swift`, `PlaceSearch.swift`: 목적지와 내비 연결
- `DeulgoTests/`, `DeulgoUITests/`: 단위 28개와 UI 2개, 총 30개가 실행 #9에서 통과
- `scripts/test_rules.cjs`: 실제 번들 규칙을 DOM 없는 JavaScript 환경에서 검증

차량 카탈로그는 기존 시제품 자료를 복사한 것으로 이번 작업에서 개별 제원을 재조사하지 않았다. 미확보값은 그대로 유지하며 판본·좌석 상태·시장 차이를 숨기지 않는다. 현재 요청은 물품명 하나를 중심으로 작성한다. 거래글의 묶음 구성·수량·종류별 크기는 자동 확정하지 않으며, 여러 종류/분해 조각 및 확인된 수량 입력은 후속 항목이다.

## 빌드

Xcode 26+, iOS 17+가 필요하다. `Deulgo.xcodeproj`를 열고 공유 Scheme `Deulgo`를 사용한다.

```sh
python3 scripts/check_structure.py
node --test scripts/test_rules.cjs
xcodebuild test -project Deulgo.xcodeproj -scheme Deulgo \
  -destination 'platform=iOS Simulator,name=<설치된 iPhone 시뮬레이터 이름>'
```

`.github/workflows/ios-check.yml`은 원본 저장소의 `main`에서 수동 실행한다. 키 없이 구조·XCTest·시뮬레이터 화면을 먼저 검사하고, 성공한 동일 커밋의 기기용 Release 빌드와 unsigned IPA 생성은 `ios-release` 환경의 본인 승인 후 진행한다. 2026-11-27 03:11 KST에 성공한 실행 #9의 기준판은 0.1.3 (4), 커밋 `21a733219b5d2f409476ddde398422c740786ddc`다. unsigned IPA는 서명/재서명 후 설치해야 하며 그대로 설치되는 파일은 아니다. GitHub Actions 산출물 보관 기간은 7일이다.

`Config/Local.xcconfig.example`을 `Config/Local.xcconfig`로 복사해 Apple 팀·확정 번들 ID·카카오 Native app key를 설정한다. 임시 번들 ID는 `com.deulgo.delivery`이며 등록·소유권 확인을 의미하지 않는다. 실제 설치 번들 ID와 카카오 iOS 설정값은 일치해야 한다. REST API/Admin 키는 앱에 넣지 않는다.

카카오 앱과 iOS 번들 ID 등록은 완료했다. GitHub의 `ios-release` 환경 비밀값 `KAKAO_NATIVE_APP_KEY`를 Release 빌드 직전에만 주입한다. 키가 없거나 잘못되면 배포용 빌드를 중단하고, 산출물에 키와 번들 ID가 올바르게 반영됐는지 값 출력 없이 검사한다. 네이버지도 부분은 Ncloud REST API 키 없이 테스트할 수 있다. 로컬 빌드의 카카오 키 공란은 앱에서 준비 안내로 처리한다.

### 키를 사용하는 빌드 승인

- 환경 `ios-release`: 저장소 소유자를 필수 승인자로 지정, 관리자 승인 우회 해제, `main` 브랜치만 허용.
- 키는 일반 Repository secret에 중복 저장하지 않는다. 워크플로에서 환경 참조를 빼면 환경 비밀값도 받을 수 없다.
- Actions 실행의 `Review deployments`에서 변경 코드와 실행 커밋을 확인한 뒤 승인한다. 단독 소유자가 직접 실행한 빌드도 승인할 수 있도록 self-review는 허용한다.
- 외부 공동작업자는 2026-11-26 확인 시 0명이다. 추후 권한 부여 및 설치 앱·토큰 관리 시 별도 검토가 필요하다.
- 환경 승인은 계정 탈취나 관리자의 보호 설정 변경까지 막지는 않는다. 공개 소스에 키를 기록하지 않지만 완성된 IPA에는 네이티브 앱 키가 포함되므로 추출 가능하다. 어드민 키·서버 비밀값은 앱에 포함하지 않는다.

앱 아이콘·스토어 설명·개인정보 정책·Apple 배포 설정·서버 기능은 출시 전에 추가해야 한다.
